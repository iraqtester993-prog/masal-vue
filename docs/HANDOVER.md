# دليل تسليم دنانير وتشغيله

تاريخ إعداد الحزمة: **2026-10-18، توقيت بغداد**. المصدر المعتمد هو **`D:\masal-vue`**، ومرجع التشغيل المنشور **`20261018-permissions138`**. أُعد المصدر ونُقل في دفعة التسليم 139، ثم حُدثت الحزمة بعد نشر الواجهة 140: تبويبان لإعدادات التطبيق والطابعات، مع عرض الطابعات للقراءة فقط وإبقاء حفظ إعدادات التطبيق. لم تتغير مصادر Backend أو Android في دفعة 140.

## ما تستلمه الشركة

المجلد يحتوي الشفرة والأصول والمخطط وتاريخ migrations وملفات تثبيت الاعتماديات والاختبارات وقوالب الاستضافة وأدوات التجهيز والبناء. Vue مشترك بين بوابات المدير والوكلاء ونقاط البيع وموقع الشركة. تطبيق Android يعرض بوابة نقطة البيع ويضيف وظائف الجهاز، ويتبع النظام نفسه.

`node_modules` و`backend/vendor` والكاش و`frontend/dist` و`android-pos/**/build` نواتج قابلة لإعادة الإنشاء. غيابها عن حزمة نظيفة مقصود، وملفات lock ومكتبات الأجهزة المرفقة تبقى ضمن المصدر. لا حاجة لنسخ Node أو PHP أو JDK أو Android SDK كاملة داخل المشروع؛ تثبت على جهاز البناء كمتطلبات قياسية.

الأرشيف خارج المصدر ويحتوي النسخ السابقة والتقارير التاريخية. [فهرسه](ARCHIVE_INDEX.md) يوضح موقعه وبصمات التحقق. احتفاظ الأدلة خارج المصدر يمنع التباسها مع ملفات الإصدار الحالي.

## متطلبات جهاز البناء

| المكوّن | المتطلب |
| --- | --- |
| PowerShell | 7 أو أحدث على Windows. |
| Node.js | 22.12 أو أحدث، مع npm. |
| PHP | 8.4.1 أو أحدث، وإضافات `composer.lock` المطلوبة؛ يشمل الاختبار SQLite وPDO. |
| Composer | الإصدار 2.10 أو أحدث، لتثبيت `backend/composer.lock` مع منع الرجوع إلى أدوات المستودعات. |
| Python | الإصدار 3.10 أو أحدث لأدوات الحزم والمراجعة. |
| Java | JDK 17 أو 21. |
| Android | SDK Platform 35 وBuild Tools 35.0.0، مع تراخيص SDK المقبولة على جهاز البناء. |

تحتاج أول عملية تجهيز اتصالًا بمستودعات npm وComposer وGradle/Android. الإصدارات المثبتة في ملفات lock هي المعتمدة، ولا يُجرى تحديث عام للاعتماديات ضمن التسليم.

حدد `MASAL_PHP` إذا لم يكن PHP الصحيح على PATH، و`MASAL_COMPOSER` لمسار `composer.phar` عند الحاجة. لـAndroid حدد `JAVA_HOME` و`ANDROID_HOME` أو `ANDROID_SDK_ROOT`. جميع مسارات المشروع في أدواته نسبية؛ مكان المصدر على D لا يتطلب تعديل الشفرة.

## تجهيز نسخة نظيفة والتحقق

انسخ المصدر إلى مجلد جديد مستقل، دون نسخ البيئة الخاصة أو الاعتماديات أو نواتج البناء القديمة، ثم نفذ من جذره:

```powershell
.\scripts\setup.ps1 -Target all
.\scripts\build.ps1 -Target all
```

يمكن استخدام `-Target frontend` أو `backend` أو `android` لفحص مجال معين. `-SkipTests` يبني دون الاختبارات ولا يعد بديلًا لقبول التسليم. تجهيز Backend يعمل دون إنشاء `.env` أو تنفيذ migrations؛ اختباره يفرض SQLite في الذاكرة وإعدادات اختبار مستقلة. Android يبني Debug افتراضيًا، ولا ينشر APK أو يغيّر رقم الإصدار.

لبناء الواجهات فقط تُنتج المداخل الأربعة داخل `frontend/dist/`. الباك لا يحتاج Node لخدمة API في الإنتاج. اختبار Android على جهاز أو محاكي وتوقيع Release لهما متطلبات منفصلة موضحة في [دليله](../android-pos/README.md).

## تشغيل محلي بحساب جديد

خطوات إنشاء البيئة والقاعدة الفارغة وأول مدير في [دليل الخادم](../backend/README.md). لا تستخدم بيئة الإنتاج لهذه الخطوات. بعد تجهيز قاعدة محلية، شغّل Backend ثم المدخل المطلوب من أوامر `dev:*` في README الجذر.

لا توجد كلمة مرور ابتدائية مسجلة في المصدر. إنشاء أول مدير تفاعلي، والبذر الافتراضي يجهز قاموس الصلاحيات فقط. التحقق من اتصال مزود خارجي يحتاج إعداداته الحقيقية ولا ينشئها التجهيز تلقائيًا.

## التسليم الخاص

تُسلّم العناصر التالية عبر مسار خاص ومحدود الوصول، مع فحص استرجاعها:

- نسخة متسقة من قاعدة التشغيل والتخزين الخاص وبيئة الخادم، مع حفظ `APP_KEY` نفسه عند نقل النظام القائم.
- بيانات الاستضافة وDNS ومهام cron واتصالات المزودين، دون نشرها في المستندات العامة.
- مفتاح توقيع Android وكلمات مروره والشهادة المطابقة للنسخة المثبتة؛ لا ينشأ مفتاح جديد عند تحديث التطبيق.
- ملكية حسابات الإدارة والوصول إلى النسخ الاحتياطية، مع تحديد مسؤول النشر والاسترجاع.

السورس لا يحل محل بيانات التشغيل أو أسرارها. كذلك لا تعني نسخة قاعدة وحدها وجود المرفقات الخاصة أو مفاتيح فك البيانات.

نسخة مفتاح إصدار Android المرفقة مشفرة في `artifacts/private/android-signing-vault.json` باستخدام AES-256-GCM واشتقاق PBKDF2-SHA256. ملف فتحها يُسلَّم بصورة خاصة خارج المصدر؛ لا تسجل محتواه في الأدلة أو الأوامر أو المستودعات. من جذر المشروع يمكن فحص الخزنة ومطابقة الشهادة دون بناء:

```powershell
.\deployment\signed_release.ps1 -UnlockFile '<مسار ملف الفتح الخاص>'
```

إضافة `-Build` تستعمل المفتاح مؤقتًا لبناء Release وتزيل الملف المؤقت وتعيد متغيرات العملية بعد الانتهاء. يستلزم ذلك جهاز بناء مجهزًا؛ لم يُنشأ APK Release جديد ضمن ترتيب التسليم. التسليم الخاص لدى المالك محفوظ داخل قسم `04 - تسليم الشركة` في أرشيف الدسكتوب، ويُنقل للشركة بقناة منفصلة عن السورس.

## النسخة المعتمدة ونتائج التحقق

Android المعتمد **1.4.10 / code 24** ومعرفه `iq.dananir.pos`. بصمة APK المرجعية:

```text
SHA-256: 5102bbd8ae694da174c9e267835e27d5068143e67da1b260a0c8fcdce6832339
```

مساره الوحيد في حزمة التسليم: `artifacts/android/dananeer-pos-1.4.10.apk`. لا تعدّ ملفات Debug أو نواتج بناء لاحق نسخة معتمدة للتوزيع دون التحقق من توقيعها وإصدارها.

سجل إصدار 138 قبل تنظيم التسليم يثبت نجاح **546 اختبار واجهة** و**42 فحص HTTPS**. مجموعات Backend المسجلة هي 269 و22 و290 و61 اختبارًا؛ فيها تداخل، ولا تُجمع لإعلان عدد اختبارات مستقل. سجل الإصدار يثبت تطابق بيانات التشغيل والمخطط وعدم تنفيذ شراء مزود أو تغيير أذون مستخدمين حقيقيين أثناء تلك الدفعة.

نتائج إصدار 138 ليست بديلًا عن نتائج تجهيز الحزمة المنقولة. تُراجع نتيجة فحص التسليم الحالية وبصمات المصدر وأدلة بناء النسخة النظيفة من الأرشيف المذكور في [فهرس الأدلة](ARCHIVE_INDEX.md).

فحص تجهيز المصدر 139 من نسخة نظيفة مستقلة أعطى النتائج التالية. نتائج Backend وAndroid وأدوات النشر أدناه تخص تلك الدفعة، وتأكد ثبات مصادرها في تحديث الواجهة 140 دون إعادة تشغيلها:

| الفحص | النتيجة |
| --- | --- |
| الواجهة | 546 اختبارًا ناجحًا، وبناء المداخل الأربعة. |
| Backend على SQLite المعزول | 987 حالة إجمالًا: 964 ناجحة، و23 متخطاة تخص قبولًا أصليًا أو خارجيًا منفصلًا؛ 10812 تأكيدًا، دون فشل. الحالات المتخطاة ليست نجاحًا. |
| Android | 64 اختبار وحدة ناجحًا وبناء Debug؛ lint دون أخطاء، مع 18 تحذيرًا مسجلة. لم تُبنَ نسخة Release جديدة. |
| أدوات حزم النشر | 26 اختبارًا ناجحًا لحدود المسارات والملفات الخاصة والروابط والتكرار والبصمات والضغط والتحقق للقراءة فقط. |
| صيانة الملفات الثابتة | 16 اختبارًا ناجحًا لحفظ الروابط والمحتوى والتوقيت والأرشفة والتحقق والاسترجاع؛ مجموع اختبارات أدوات النشر والصيانة 42. |

كذلك جُهزت حزمة نشر من المصدر وفُحصت جميع ملفاتها وCRC أرشيفاتها ببصمة manifest مثبتة، ونجح `hosting_guard.py` على تركيب استضافة اصطناعي مع ثبات جميع الملفات قبل الفحص وبعده. هذه تجربة أدوات للقراءة فقط، وليست نشرًا لتلك الحزمة أو اتصالًا بقاعدة الإنتاج.

`HANDOVER-MANIFEST.json` في جذر المصدر هو بيان ملفات حزمة التسليم وبصماتها، مع تمييز Backend 138 وتنظيم التسليم 139 عن تحديث الواجهة 140. لا يشمل `.git` أو النواتج المتولدة. تُراجع بصماته عند نقل السورس إلى جهاز الشركة.

الحدود المسجلة: لا اختبار طباعة ورقية جديد، ولا تجربة إنتاج مصادق عليها لجميع الصفحات، ولا قياس شامل لزمن التنقل على أجهزة المستخدم. النجاح المحلي لا يثبت تحمل الحمل المتوقع أو جميع شروط المزودين والأجهزة. تُسجّل تجارب MariaDB/MySQL والاستعادة والمحاكي والجهاز الفعلي كل على حدة.

## تحديث الواجهة 140

فُصلت إعدادات تطبيق دنانير والطابعات المدعومة إلى تبويبين. زر حفظ إعدادات التطبيق باقٍ في تبويبه، والطابعات المدعومة تعرض اسم العرض والمحرك وعبارة المطابقة وحالتها للقراءة فقط، دون أزرار الإضافة والحفظ والتفعيل والحذف. اسم العرض هو الاسم الظاهر للمستخدم، والمحرك يحدد مسار اتصال الطابعة وطريقة الطباعة، وعبارة المطابقة تساعد على مطابقة اسم الجهاز المكتشف مع تعريفه.

نجح في هذه الدفعة 551 اختبار واجهة، منها 15 اختبارًا مخصصًا للإعدادات، وبناء البوابات الثلاث. نجحت أربع حالات معاينة على مقاسي الهاتف والتابلت وفي الوضعين الفاتح والداكن. فُحصت ملفات الواجهات المنشورة بالبصمات، مع بقاء Backend 138 وAPK 1.4.10 دون تغيير. تفاصيل القبول وأدلة النشر محفوظة في مرجع دفعة 140 ضمن فهرس الأرشيف.

## تشغيل الاستضافة لاحقًا

اتبع [دليل النشر](../deployment/README.md): حزمة مجمدة ببصماتها، نسخة استرجاع محققة، تجهيز خاص ثم تفعيل محروس، وفحص قبل وبعد. تنظيف الاستضافة يقتصر على ملفات مثبت أنها غير مستخدمة ومؤرشفة؛ الملفات التي تحتاجها جلسات مفتوحة أو Service Worker لا تحذف لمجرد أن اسمها مختلف.

Git مؤجل في هذا التسليم حسب طلب المالك. تنظيم المصدر والنشر لا يتطلب إنشاء مستودع أو دفع ملفات إليه.
