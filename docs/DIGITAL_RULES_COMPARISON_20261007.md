# تدقيق الرابعة و Topup مقابل مخطط المستخدم — 2026-10-07

**النتيجة: التنفيذ لا يطابق المخطط بالكامل، والخدمتان غير مهيأتين للبيع فعليًا في قاعدة الإنتاج الحالية. هذه مراجعة فقط؛ لم يتغير كود التطبيق أو إعداداته أو توكناته.**

فُحص الكود والواجهة المنشورة ومخطط قاعدة البيانات وفهارس ومحفزات MySQL الفعلية. تطابقت بصمات 17 ملفًا من منطق الباكند المدروس مع الاستضافة (backend 20261007-parity-08b ؛ الواجهة المنشورة 20261007-layout-11d). لم يُنفذ شراء أو حجز أو تعبئة أو طلب مزود باستخدام مفتاح حقيقي. النسخة الجديدة من وثيقة الرابعة جُلبت علنًا دون توكن.

## واقع الاستضافة

قراءة MySQL في معاملة READ ONLY: ربط Topup واحد active=true لكنه بلا credential وبلا رصيد معروف؛ لا ربط للرابعة؛ صفر لقطات كتالوج وعروض ومنح وطلبات ومحاولات. purchases_enabled=true بوابة عامة، لكنها لا تجعل الربط غير المكتمل صالحًا للبيع. فهارس منع تكرار الطلبات والمحاولات ومراجع الشركة ومحفزات عدم تغيير التاريخ موجودة. لم تُطبع أي مفاتيح أو رموز بطاقات أو بيانات زبائن.

## الاختبارات المشغّلة الآن وحدود الإثبات

- DigitalServicesTest + DashboardDigitalReadTest: **53 حالة ناجحة، 955 assertion**؛ SQLite مؤقتة، Http::fake و preventStrayRequests. زمن الاختبارات المبلّغ 36.226 ثانية.
- frontend digital-model/digital-render/shell-navigation/sales-render/reports: **30 اختبارًا ناجحًا**؛ تشمل نماذج البيانات و SSR والتنقل، وليست كلها اختبارات متصفح.
- فحوص تدقيق مستقلة داخل deployment/.local: **6 حالات ناجحة، 70 assertion**: أربع حالات توثق فجوات موجودة (p1–p4)، وحالتان تثبتان بقاء نجاح Topup عند فشل inventory ومنع إشعارات POS رغم صلاحية متعارضة (p5–p6). نجاح فحص الفجوة يعني إعادة إنتاج الخلل، وليس سلامة السلوك.
- فشل التشغيل الأول لأحد فحوص التدقيق بسبب استخدام مسار summary خاطئ في الفحص نفسه؛ صُحح إلى orders/summary وأعيد التشغيل النهائي ونجح. لم يُعدّل التطبيق لتجاوز اختبار.
- معاينة المتصفح الحي: اسم خدمات API ، الربط الموجود، نموذج تعديل Topup وحقل توكن فارغ، وترتيب الحقول. فئات ومنح الإنتاج فارغة؛ لم تُنشأ بيانات وهمية لإظهار نجاح. لم يُفحص كل هاتف/وضع ليلي بصريًا.
- نتائج المحاكاة لا تثبت قبول الشركة الفعلي ولا تحاكي سباق MySQL متعدد العمليات. قراءة MySQL أثبتت البنية الفعلية فقط؛ تشغيل اختبارات المنطق كان على SQLite.
