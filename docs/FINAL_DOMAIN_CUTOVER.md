إنشاء النطاقات وفحص الشهادات اتبعا APIs المثبتة على السيرفر والمراجع الرسمية: [SubDomain addsubdomain](https://api.docs.cpanel.net/specifications/cpanel.openapi/subdomain/subdomain-addsubdomain) و[SSL start_autossl_check](https://api.docs.cpanel.net/specifications/cpanel.openapi/auto-generated-ssl-certificates/ssl-start_autossl_check).

## تصحيحات ظهرت أثناء التنفيذ

1. بيانات DomainInfo للنطاق الجديد لم تحتوي phpversion فور إنشائه؛ تحققت نسخة PHP وFPM من LangPHP مباشرة وأكملت نفس النطاقات دون إعادة إنشائها.
2. إعداد تحويل HTTPS في cPanel أعاد نجاحًا، لكن HTTP الفعلي بقي 200؛ أضيف التحويل داخل htaccess وفُحص فعليًا حتى أصبح 308.
3. ErrorDocument الموروث حول خطأ API القديم إلى رابط آخر؛ ثُبت ErrorDocument default للـ404/410 وأعيد فحص تعطيل الكاتب حتى نجحت الحالات التسع.

## حدود الإنجاز وخطة الرجوع

الروابط النهائية فعالة للتطوير. تشغيل الأعمال التجارية الكامل، ومطابقة كامل المشروع 100%، والمخزون والطلبيات والدفتر المالي والبيع والطباعة والخدمات الخارجية واللغات والتقارير ما زالت مراحل مستقلة. قبول تنزيل CSV من متصفح المستخدم بقي مفتوحًا؛ نجاح API لا يثبت تنزيل الملف من واجهة المتصفح.

المصدر القديم immutable محفوظ للمقارنة، ولم تمسح بيانات المتصفح القديم ضمن القطع. [الحصر الكامل](ORIGINAL_PROJECT_INVENTORY.md) يبين الصفحات والأزرار والاعتماديات، و[خطة المتابعة](../MIGRATION_PLAN.md) هي مرجع الإنجاز.

لإرجاع الخدمة عند الحاجة: أوقف كتابة الباك النهائي، وخذ نسخة من **البيانات الجديدة أولًا**، وحدد هل يلزم إرجاع ملفات فقط أو schema وبيانات؛ لا تحول مباشرة إلى قاعدة التجربة المجمدة لأنها لن تحتوي أعمالًا أضيفت بعد القطع. إصدارات ونسخ ما قبل القطع محفوظة، وملفات htaccess السابقة للبوابات التجريبية داخل `/home/dananiriq/masal-staging/.local/retired-staging-20261006-135250`. تفعيل أي كاتب قديم يتطلب مطابقة البيانات الحالية وإعادة التوجيه والبيئة عمدًا. لم تنفذ تجربة رجوع كاملة لهذه الدفعة؛ الاستيراد إلى قاعدة جديدة ومقارنة 30 جدولًا إثبات نقل، وليس إثبات خطة rollback كاملة.
