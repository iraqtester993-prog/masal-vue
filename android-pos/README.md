# تطبيق دنانير على Android

المصدر الأصلي لنسخة **1.4.10**، `versionCode=24`، ومعرف التطبيق **`iq.dananir.pos`**. الحد الأدنى Android **7.0 / API 24**، والهدف وCompile SDK هما **35**. التطبيق يعرض `https://pos.dananir-iq.com` داخل WebView ويصلها بوظائف الجهاز والطباعة من خلال الجسر الأصلي.

## البناء من المصدر

المطلوب JDK **17 أو 21**، وAndroid SDK **35** وBuild Tools **35.0.0**. Gradle Wrapper يستخدم **8.13** وAndroid Gradle Plugin **8.11.1**. حدد `JAVA_HOME` و`ANDROID_HOME` أو `ANDROID_SDK_ROOT` على جهاز البناء.

من جذر المشروع:

```powershell
.\scripts\setup.ps1 -Target android
.\android-pos\scripts\build.ps1 -Configuration Debug
```

البناء يشغّل اختبارات الوحدة وlint ويبني APK للتطوير. المخرجات المتجددة في `android-pos/app/build/outputs/apk/`. هذه المخرجات ليست بديلًا عن APK الموقع المعتمد للتثبيت فوق النسخة التجارية.

نسخة التسليم المعتمدة في `../artifacts/android/dananeer-pos-1.4.10.apk` وبصمتها موثقة في [دليل التسليم](../docs/HANDOVER.md).

بناء Release يتطلب متغيرات البيئة الأربعة التالية، من تسليم التوقيع الخاص:

```text
DANANEER_SIGNING_STORE
DANANEER_SIGNING_STORE_PASSWORD
DANANEER_SIGNING_KEY_ALIAS
DANANEER_SIGNING_KEY_PASSWORD
```

```powershell
.\android-pos\scripts\build.ps1 -Configuration Release
```

يُرفض بناء Release عند نقص بيانات التوقيع؛ لا يوجد مفتاح تطوير بديل. يلزم المفتاح والشهادة نفسيهما لتحديث نسخة مثبتة دون استبدال هوية التطبيق. لا تكتب كلمات المرور في الأوامر أو ملفات المصدر.

مفتاح التحديث الأصلي مرفق بصورة مشفرة في `../artifacts/private/android-signing-vault.json`، وملف فتحه يسلم خارج المصدر. الأداة `.\deployment\signed_release.ps1 -UnlockFile '<مسار خاص>'` من جذر المشروع تفحصه دون بناء؛ إضافة `-Build` تبني باستخدام مفتاح مؤقت. طريقة التسليم وحدودها في [دليل التسليم](../docs/HANDOVER.md).

## مكتبات الأجهزة

تتضمن الحزمة مكتبات الأجهزة المطلوبة للبناء، مع بيان الملفات والبصمات في ملف SDK المرفق. `scripts/prepare-sdk.ps1` يتحقق منها؛ لا يعتمد على ملفات عابرة في قرص آخر. مكتبات ROVOO وZCS المورّدة ليست موصوفة تلقائيًا بترخيص المشروع؛ تحتفظ الشركة بشروط المورد وحقوق التوزيع.

المحركات تشمل Bluetooth Classic SPP وواجهات الأجهزة الداخلية المدعومة في المصدر. اسم الطابعة أو ظهور الخدمة لا يثبت خروج الورقة أو توافق كل جهاز. سجل الطباعة المحلي يحمي من التكرار ويحفظ الحالة دون محتوى الوصل أو PIN، وإعادة الطباعة تتبع العملية الموجودة في النظام.

## تحديث الواجهة والتحقق

تحديث الواجهة المستضافة يصل إلى التطبيق الحالي. تعديل Java أو SDK أو موارد Android أو الصلاحيات الأصلية يتطلب APK جديدًا. بيانات API والعمليات الخاصة لا تتحول إلى مخزون بيع دون اتصال.

اختبارات الوحدة وlint والبناء لا تثبت الطباعة الورقية أو الاقتران على كل عتاد. اختبار الجهاز الحقيقي والورقة واختبارات instrumentation على المحاكي يسجل كل منها منفصلًا. النسخة المرجعية 1.4.10 لم يُعَد بناؤها لمجرد تنظيم حزمة التسليم. نتائج الفحص الحالية ومسار النسخة المعتمدة في [دليل التسليم](../docs/HANDOVER.md).
